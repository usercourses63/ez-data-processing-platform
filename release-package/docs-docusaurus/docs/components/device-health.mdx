# Device Health Component

Monitors the health status of NAS devices and admin servers with automatic health checks, latency tracking, and consecutive failure detection.

## Features

- **Automatic Health Checks**: Quartz.NET job running every 30 seconds
- **Consecutive Failure Tracking**: Graduated status: Healthy / Degraded / Down
- **Latency Monitoring**: Configurable degraded thresholds per device type
- **Status Cards**: Color-coded health status cards with key metrics
- **Summary Bar**: Aggregated health overview showing total/healthy/degraded/down counts
- **SignalR + Polling**: Real-time updates via SignalR with React Query polling fallback (15s)

## Data Model

### DeviceHealthStatus

```typescript
type DeviceHealthStatus = 'Healthy' | 'Degraded' | 'Down' | 'Disabled';
```

### DeviceHealthInfo

```typescript
interface DeviceHealthInfo {
  DeviceId: string;
  DeviceName: string;
  DeviceType: string;          // 'NAS' | 'AdminServer'
  DeviceSubType?: string;      // 'FTP' | 'SFTP' | 'HTTP' | 'Kafka' etc.
  Role: string;                // 'Input' | 'Output' | 'Backup' | 'Both'
  Status: DeviceHealthStatus;
  LatencyMs?: number;          // Last measured latency in milliseconds
  LastCheckTime?: string;      // ISO 8601 timestamp
  ErrorMessage?: string;       // Error details when Status is Down
  UptimePercentage24h: number; // 0-100 uptime percentage
  IsActive: boolean;
}
```

### DeviceHealthStatusResponse

```typescript
interface DeviceHealthStatusResponse {
  TotalDevices: number;
  HealthyCount: number;
  DegradedCount: number;
  DownCount: number;
  DisabledCount: number;
  NasDevices: DeviceHealthInfo[];
  AdminServers: DeviceHealthInfo[];
}
```

## Health Check Configuration

### Quartz.NET Job

The backend runs a health check job every 30 seconds using Quartz.NET:

- **Interval**: 30 seconds
- **Scope**: All active NAS devices and admin servers
- **Storage**: MongoDB with TTL for historical data
- **Consecutive Failure Tracking**: Determines device status based on consecutive check failures

### Status Determination

| Consecutive Failures | Status | Description |
|---------------------|--------|-------------|
| 0 | Healthy | Device responding normally |
| 1-2 | Degraded | Intermittent failures or high latency |
| 3+ | Down | Device unreachable or consistently failing |

### Latency Thresholds

Devices are marked as Degraded when response latency exceeds the threshold, even if the check succeeds:

| Device Type | Degraded Threshold | Description |
|-------------|-------------------|-------------|
| NAS | 2000 ms | NFS mount and file system operations |
| AdminServer | 5000 ms | Protocol connection (FTP, SFTP, HTTP, Kafka) |

### Data Fetching

The component uses dual data sources:

```typescript
// SignalR: real-time updates when connected
const { deviceHealth, isConnected } = useMonitoringHub(hubUrl);

// React Query: polling fallback when SignalR disconnected
const { data: polledData } = useQuery<DeviceHealthStatusResponse>({
  queryKey: ['device-health-status'],
  queryFn: getDeviceHealthStatus,
  refetchInterval: isSignalRConnected ? false : 15000,  // 15s polling
  enabled: !isSignalRConnected,
  staleTime: 10000,
});

// Prefer SignalR data, fall back to polled data
const data = signalRData ?? polledData;
```
