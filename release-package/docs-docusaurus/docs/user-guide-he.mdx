## סקירה כללית

### מה זה EZ Platform?

פלטפורמת EZ היא מערכת לעיבוד אוטומטי של נתונים המאפשרת:

- **גילוי קבצים אוטומטי** ממקורות שונים (תיקיות, SFTP, FTP, HTTP, Kafka, NAS/NFS)
- **המרת פורמטים** (CSV, JSON, XML, Excel)
- **אימות נתונים** לפי סכמה שהוגדרה מראש (JSON Schema 2020-12)
- **שליחה ליעדים מרובים** (תיקיות, Kafka topics)
- **ניהול רשומות שגויות** וטיפול בשגיאות
- **מעקב ומדדים** בזמן אמת
- **ניהול התקני NAS** עם PV/PVC אוטומטי

### מה חדש בגרסה v0.2.0

- תמיכה בהתקני NAS/NFS עם אינטגרציית Kubernetes
- **ניטור מערכת בזמן אמת** עם SignalR WebSocket - עדכונים חיים לסטטוס שירותים, Kafka, ו-traces
- **בריאות מכשירים** - ניטור אוטומטי של התקני NAS ושרתי Admin עם זיהוי תקלות
- **OTEL Observability** - אימות מלא של 8 שירותים עם logs, traces, ו-metrics (24/24 בדיקות)
- בדיקות פרוטוקול מקיפות (FTP, SFTP, HTTP, S3, SMB, NFS, Kafka, Local)
- אינטגרציית file-simulator לבדיקות רב-פרוטוקוליות
- בדיקות E2E מורחבות עם Playwright
- תיעוד משופר עם פורטל Docusaurus
- אוטומציית CI/CD מלאה עם GitHub Actions
- Helm Charts מעודכנים לגרסה 0.2.0

### מה חדש בגרסה v0.3.0

- **סנכרון בזמן אמת (SignalR)** - שינויים שנעשים על ידי משתמשים אחרים מופיעים אוטומטית
- **תגיות סטטוס NAS** - תצוגת סטטוס מתורגמת (מחובר/לא מחובר) בעברית ואנגלית
- **מחיקת NAS אוטומטית** - מחיקת התקן NAS מסירה אוטומטית משאבי PV/PVC מ-Kubernetes
- **ניטור תורי RabbitMQ** - החלפת ניטור Kafka פנימי בניטור RabbitMQ
- **תצוגת Traces משופרת** - שמות שירותים מקוצרים, תזמון יחסי
- **בריאות מכשירים משופרת** - תמיכה בשני פורמטי JSON, גיבוי HTTP Polling

### למי המערכת מיועדת?

- **מנהלי נתונים**: הגדרה וניהול של מקורות נתונים והתקני NAS
- **אנליסטים**: הגדרת סכמות ותהליכי אימות
- **מפעילי מערכת**: מעקב אחר עיבוד ותזמון
- **מנהלי איכות**: זיהוי וטיפול בשגיאות

## התחברות למערכת

### גישה למערכת

**כתובת:** http://localhost:7000 (פיתוח) או כתובת הייצור שהוגדרה

**גרסה v0.2.0:**
- אין צורך בהתחברות (לא דורש שם משתמש וסיסמה)
- גישה ישירה לממשק המשתמש
- גרסאות עתידיות יכללו מערכת הרשאות

### תפריט ניווט

הסרגל הצדדי (מימין) כולל:
- **מקורות נתונים**: ניהול מקורות הנתונים שלך
- **רשומות לא תקינות**: צפייה ותיקון של רשומות שנכשלו באימות
- **התרעות**: ניהול התראות על אירועים במערכת
- **דשבורד**: תצוגה כללית של המערכת
- **הגדרות מערכת**: ניהול קטגוריות, התקני NAS והגדרות (מנהלי מערכת)

### כפתור עזרה

בחלק העליון של המסך תמצא כפתור עזרה (סימן שאלה). לחיצה עליו תפתח את פורטל התיעוד הזה בלשונית חדשה.

## ניהול מקורות נתונים

### מה זה מקור נתונים?

מקור נתונים מגדיר:
- **מהיכן** לקחת קבצים (תיקייה, שרת SFTP, HTTP API, NAS, וכו')
- **איזה פורמט** הקבצים (CSV, JSON, XML, Excel)
- **איך לאמת** את הנתונים (JSON Schema)
- **לאן לשלוח** את הנתונים המעובדים
- **מתי לעבד** (תזמון אוטומטי או ידני)

---

### יצירת מקור נתונים חדש

#### שלב 1: מידע בסיסי

1. לחץ על "מקורות נתונים" בתפריט הצדדי
2. לחץ על כפתור "הוסף מקור נתונים"
3. מלא פרטים בסיסיים:

**שם מקור הנתונים:**
- שם מזהה ייחודי (לדוגמה: "נתוני מכירות חודשיים")
- חובה, 2-100 תווים

**שם הספק:**
- שם הגוף המספק את הנתונים (לדוגמה: "חברת ABC")
- חובה, 2-50 תווים

**קטגוריה:**
- בחר קטגוריה מהרשימה (מכירות, כספים, מלאי, וכו')
- רשימת הקטגוריות מנוהלת על ידי מנהל המערכת

**תקופת שמירה:**
- כמה ימים לשמור קבצים מעובדים (ברירת מחדל: 30 יום)

**תיאור:**
- הסבר מפורט על מקור הנתונים (אופציונלי, עד 500 תווים)

**סטטוס:**
- פעיל / לא פעיל
- רק מקורות פעילים מעובדים על ידי המערכת

4. לחץ "המשך" למעבר לכרטיסייה הבאה

#### שלב 2: הגדרות חיבור

בחר סוג חיבור:

**תיקיה מקומית (Local):**
- נתיב מלא לתיקיה (לדוגמה: `/data/uploads`)
- המערכת תסרוק קבצים חדשים בתיקייה

**SFTP:**
- כתובת שרת (לדוגמה: `sftp.example.com`)
- שם משתמש וסיסמה
- נתיב בשרת
- יציאה (ברירת מחדל: 22)

**FTP:**
- כתובת שרת
- שם משתמש וסיסמה (אופציונלי)
- נתיב בשרת
- יציאה (ברירת מחדל: 21)

**HTTP API:**
- כתובת URL (לדוגמה: `https://api.example.com/data`)
- Headers (אופציונלי)
- שיטת אימות (API Key, Bearer Token)

**Kafka:**
- כתובת Broker (לדוגמה: `kafka.example.com:9092`)
- שם Topic
- Consumer Group
- פרוטוקול אבטחה (PLAINTEXT, SASL_SSL, וכו')

**NAS/NFS (חדש בגרסה v0.2.0):**
- בחר התקן NAS מהרשימה הנפתחת
- ציין נתיב בתוך התקן ה-NAS
- ראה סעיף "ניהול התקני NAS" להגדרת התקנים

**S3/MinIO:**
- Endpoint URL
- Access Key ו-Secret Key
- שם Bucket
- Region (אופציונלי)

**SMB/CIFS:**
- כתובת שרת (לדוגמה: `\\server\share`)
- שם משתמש וסיסמה
- Domain (אופציונלי)

**בדיקת חיבור:**
- לחץ "בדוק חיבור" לאימות שהחיבור עובד
- סטטוס יופיע: מוצלח או נכשל עם הודעת שגיאה

#### שלב 3: הגדרות קובץ

**פורמט קובץ:**
- CSV, JSON, XML, Excel
- המערכת תמיר אוטומטית לפורמט אחיד

**הגדרות CSV:**
- **מפריד (Delimiter)**: פסיק, נקודה-פסיק, Tab, צינור
- **קידוד (Encoding)**: UTF-8 (מומלץ), Windows-1255, ISO-8859-8
- **שורת כותרת**: האם השורה הראשונה מכילה שמות עמודות

**תבנית שם קובץ (Pattern):**
- Regex לסינון קבצים (לדוגמה: `sales-.*\.csv`)
- רק קבצים התואמים לתבנית יעובדו

**גודל מקסימלי:**
- הגבלת גודל קובץ (MB)
- ברירת מחדל: 100MB

#### שלב 4: הגדרת Schema

**מה זה Schema?**
- JSON Schema המגדיר את מבנה הנתונים הצפוי (תקן 2020-12)
- כללי אימות לכל שדה
- שדות חובה ואופציונליים

**אפשרויות:**

**1. בחירת Schema קיים:**
- בחר מרשימת Schemas שהוגדרו במערכת
- מתאים כאשר יש כבר Schema מוכן

**2. יצירת Schema חדש:**
- לחץ "צור Schema חדש"
- השתמש בעורך החזותי
- הוסף שדות ואימותים
- שמור Schema

**3. ללא Schema:**
- המערכת תקבל את כל הנתונים ללא אימות
- לא מומלץ לסביבת ייצור

**עורך Schema החזותי:**
- הוסף שדות: שם, סוג (מחרוזת, מספר, תאריך, וכו')
- הגדר אימותים: אורך מינימלי/מקסימלי, תבנית Regex, טווח ערכים
- סמן שדות חובה
- הוסף תיאור לכל שדה

**תבניות Schema:**
- לקוח ישראלי (עם ת"ז, טלפון, כתובת)
- עסקה פיננסית
- קטלוג מוצרים
- רשומת עובד
- חשבונית מע"מ

#### שלב 5: תזמון

**תדירות עיבוד:**

**ידני:**
- המערכת לא תעבד אוטומטית
- ניתן להפעיל ידנית מרשימת מקורות הנתונים

**מתוזמן:**
- **כל דקה**: בדיקה כל דקה
- **כל 5 דקות**: בדיקה כל 5 דקות
- **כל 15 דקות**: בדיקה כל 15 דקות
- **כל 30 דקות**: בדיקה כל חצי שעה
- **כל שעה**: בדיקה כל שעה
- **יומי**: פעם ביום בשעה קבועה
- **שבועי**: פעם בשבוע ביום ובשעה קבועים
- **חודשי**: פעם בחודש ביום ובשעה קבועים
- **מותאם אישית (Cron)**: הגדרת ביטוי Cron מותאם

**דוגמאות Cron:**

```
*/5 * * * *    - כל 5 דקות
```

**חלון זמן:**
- הגדר טווח שעות לעיבוד (לדוגמה: 08:00-18:00)
- מחוץ לחלון, המערכת לא תעבד קבצים

#### שלב 6: כללי אימות

**פעולה בעת שגיאת אימות:**

**המשך עיבוד:**
- רשומות תקינות עוברות הלאה
- רשומות שגויות נשלחות ל"רשומות לא תקינות"
- מומלץ לרוב המקרים

**הפסק עיבוד:**
- כל שגיאת אימות עוצרת את העיבוד
- כל הקובץ נדחה
- מתאים לנתונים קריטיים

**אחוז מקסימלי של שגיאות:**
- הגדר סף (לדוגמה: 10%)
- אם אחוז השגיאות גבוה מהסף, העיבוד נעצר

#### שלב 7: התראות

**התראות על:**
- קובץ חדש התגלה
- אימות הושלם בהצלחה
- שגיאות באימות
- שגיאות בעיבוד
- פלט הושלם

**ערוצי התראה:**
- Email (פיצ'ר עתידי)
- Webhook (פיצ'ר עתידי)
- UI notifications (פעיל)

#### שלב 8: יעדי פלט

**הגדר לאן לשלוח נתונים מעובדים:**

**תיקייה (Folder):**
- נתיב יעד
- פורמט: JSON, CSV, XML
- שם קובץ (תבנית עם placeholders)

**Kafka Topic:**
- שרת Kafka
- שם Topic
- פורמט הודעה: JSON
- כולל Invalid Records: כן/לא

**NAS/NFS:**
- בחר התקן NAS מהרשימה
- ציין נתיב יעד בתוך ההתקן

**יעדים מרובים:**
- ניתן להוסיף מספר יעדי פלט
- לחץ "הוסף יעד" להוספת יעד נוסף
- לדוגמה: שליחה לתיקייה + Kafka Topic

#### שלב 9: שמירה

1. בדוק שכל השדות הנדרשים מולאו
2. לחץ "צור" (או "עדכן" במצב עריכה)
3. מקור הנתונים יופיע ברשימה
4. המערכת תתחיל לעבד קבצים לפי התזמון שהוגדר

## ניהול התקני NAS

### מה זה NAS?

NAS (Network Attached Storage) הוא התקן אחסון ברשת המשמש לאחסון קבצים משותפים. בגרסה v0.2.0 נוספה תמיכה מלאה בניהול התקני NAS עם אינטגרציה ל-Kubernetes.

### גישה לניהול NAS

1. עבור ל"הגדרות מערכת" בתפריט הצדדי
2. בחר בלשונית "התקני NAS"
3. תוצג רשימה של כל התקני ה-NAS המוגדרים

### הוספת התקן NAS חדש

1. לחץ על כפתור "הוסף התקן NAS"
2. מלא את הפרטים הבאים:

**שם התקן:**
- שם מזהה ייחודי (לדוגמה: "NAS-Prod-01")
- חובה

**כתובת שרת NFS:**
- כתובת IP או hostname של שרת ה-NFS (לדוגמה: `192.168.1.100`)
- חובה

**נתיב Export:**
- הנתיב ב-NAS שיהיה זמין (לדוגמה: `/exports/data`)
- חובה

**קיבולת (GB):**
- גודל האחסון המוקצה
- ברירת מחדל: 100GB

**תפקיד:**
- **קלט (Input)**: לקריאת קבצים בלבד (כחול)
- **פלט (Output)**: לכתיבת קבצים בלבד (ירוק)
- **גיבוי (Backup)**: לגיבוי נתונים (כתום)
- **קלט ופלט (Both)**: קריאה וכתיבה (סגול)

**תיאור:**
- הסבר על התקן ה-NAS (אופציונלי)

3. לחץ "צור"
4. המערכת תיצור אוטומטית PersistentVolume ו-PersistentVolumeClaim ב-Kubernetes

### סטטוס התקן NAS

כל התקן מציג צבע סטטוס:
- **ירוק**: פעיל - PV/PVC מחוברים ופעילים
- **צהוב**: ממתין - יצירת משאבים בתהליך
- **אדום**: שגיאה - בעיית חיבור או הגדרה

### תגיות סטטוס (v0.3.0)

בגרסה v0.3.0, כל התקן NAS מציג תגיות סטטוס מתורגמות:

| תגית | צבע | משמעות |
|-------|------|---------|
| **מחובר** | ירוק | התקן NFS זמין ומגיב |
| **לא מחובר** | אדום | אין תקשורת עם ההתקן |
| **PVC מחובר** | ירוק | PersistentVolumeClaim מחובר ל-PV |
| **PV נוצר** | כחול | PersistentVolume נוצר ב-Kubernetes |
| **לא מוקצה** | אפור | התקן לא הוקצה עדיין |

התגיות מוצגות בעברית או באנגלית לפי שפת הממשק שנבחרה.

### סנכרון בזמן אמת (v0.3.0)

שינויים שמבוצעים על ידי משתמשים אחרים במערכת מופיעים אוטומטית ללא צורך ברענון ידני. לדוגמה:
- משתמש אחר מוסיף התקן NAS - ההתקן מופיע ברשימה שלך מיד
- משתמש אחר מוחק התקן - ההתקן נעלם מהרשימה שלך
- שינוי סטטוס - סטטוס ההתקן מתעדכן בזמן אמת

סנכרון זה מתבצע באמצעות חיבור SignalR WebSocket.

### מחיקת התקן NAS (v0.3.0)

## הגדרות ארכיון

### מה זה חילוץ ארכיון?

המערכת תומכת בחילוץ אוטומטי של קבצים מארכיונים. כאשר מקור הנתונים מגדיר שהקבצים הנכנסים הם ארכיונים, המערכת מחלצת את הקבצים ומעבדת אותם.

### פורמטים נתמכים

| פורמט | סיומות | הערות |
|-------|--------|-------|
| ZIP | `.zip` | הפורמט הנפוץ ביותר |
| TAR.GZ | `.tar.gz`, `.tgz` | נפוץ במערכות Linux |
| RAR | `.rar` | פורמט קנייני |
| 7-Zip | `.7z` | דחיסה גבוהה |

### הגדרת חילוץ ארכיון במקור נתונים

בלשונית **חיבור** של מקור הנתונים:

1. **סמן** את האפשרות "מקור מכיל ארכיונים"
2. **בחר סוג ארכיון:**
   - **אוטומטי**: זיהוי לפי סיומת הקובץ או תוכנו
   - או בחר פורמט ספציפי (ZIP, TAR.GZ, RAR, 7Z)
3. **תבנית חילוץ** (אופציונלי):
   - הזן תבנית glob לסינון קבצים (לדוגמה: `*.csv`)
   - ריק = חלץ את כל הקבצים
4. **סיסמת ארכיון** (אופציונלי):
   - אם הארכיון מוגן בסיסמה, הזן אותה כאן
5. **ארכיונים מקוננים**:
   - סמן אם יש ארכיונים בתוך ארכיונים
   - המערכת תחלץ רקורסיבית

### דוגמה לתהליך חילוץ

עבור מקור נתונים שמקבל קובץ `daily_reports.zip` המכיל:

<div dir="ltr" style={{fontFamily: 'monospace', background: '#f5f5f5', padding: '10px', borderRadius: '4px'}}>

```
daily_reports.zip
├── sales.csv

├── reports/
│   ├── summary.xlsx
│   └── details.json
```

</div>

**עם תבנית `*.csv`:**
- המערכת תעבד רק את `sales.csv` ו-`inventory.csv`

**עם תבנית ריקה:**
- כל הקבצים יעובדו

**עם "ארכיונים מקוננים" מסומן:**
- גם קבצים בתוך `backup.zip` יחולצו

## הגדרת סכמות

### סקירת Schema

JSON Schema מגדיר:
- **מבנה הנתונים**: אילו שדות צריכים להיות
- **סוג הנתונים**: מחרוזת, מספר, תאריך, וכו'
- **כללי אימות**: אורך, תבנית, טווח ערכים
- **שדות חובה**: אילו שדות חייבים להופיע

---

### יצירת Schema חדש

#### דרך 1: תבנית מוכנה

1. עבור ל"ניהול Schema"
2. לחץ "השתמש בתבנית"
3. בחר תבנית:
   - **לקוח ישראלי**: שדות לקוח עם ת"ז, טלפון, כתובת
   - **עסקה פיננסית**: סכום, תאריך, סוג עסקה
   - **קטלוג מוצרים**: שם, מחיר, מלאי
   - **רשומת עובד**: שם, תפקיד, משכורת
   - **חשבונית מע"מ**: מספר, תאריך, סכום, מע"מ
4. התאם אישית לפי הצורך
5. שמור Schema

#### דרך 2: עורך חזותי

1. לחץ "צור Schema חדש"
2. מלא פרטים בסיסיים:
   - **שם Schema**: שם טכני באנגלית (lowercase, underscores)
   - **שם תצוגה**: שם בעברית
   - **תיאור**: הסבר מה Schema זה מאמת

3. הוסף שדות:
   - לחץ "הוסף שדה"
   - **שם שדה**: שם באנגלית (לדוגמה: `customer_id`)
   - **שם תצוגה**: שם בעברית (לדוגמה: "מספר לקוח")
   - **סוג**: בחר מהרשימה
   - **חובה**: סמן אם השדה הוא חובה

4. הגדר אימותים לכל שדה:

**עבור מחרוזת (String):**
- אורך מינימלי/מקסימלי
- תבנית Regex (לדוגמה: ת"ז ישראלית, מספר טלפון)
- פורמט (email, uri, date-time)

**עבור מספר (Number):**
- ערך מינימלי/מקסימלי
- כפולה של (multipleOf)

**עבור תאריך:**
- פורמט: date, date-time, time
- טווח תאריכים

**עבור boolean:**
- ערכים: true/false

5. שמור Schema
6. ניתן לקשר Schema למקור נתונים

---

### עריכת Schema קיים

1. ברשימת Schemas, לחץ "ערוך"
2. ערוך שדות או אימותים
3. שמור שינויים

**שים לב:**
- שינוי Schema משפיע על קבצים עתידיים בלבד
- קבצים שכבר עובדו לא מושפעים

## ניטור מערכת

### סקירה כללית

דף ניטור המערכת (System Monitoring) מציג בזמן אמת את מצב כל רכיבי הפלטפורמה. הדף משתמש בחיבור SignalR WebSocket לעדכונים חיים.

### גישה לניטור

1. לחץ על **"ניטור"** בתפריט הצדדי
2. הדף מציג כותרת עם מידע על ה-cluster וסטטוס החיבור

### סטטוס חיבור

בפינה העליונה מוצגת נקודת סטטוס:
- **ירוק**: מחובר - עדכונים חיים באמצעות SignalR
- **צהוב**: מתחבר מחדש - ניתוק זמני, המערכת מנסה להתחבר
- **אדום**: מנותק - אין חיבור SignalR, המערכת משתמשת בנתוני גיבוי

### לשוניות

הדף מחולק ללשוניות:

| לשונית | תוכן |
|---------|-------|
| **סקירה** | זרימת Pipeline, אירועים, בריאות שירותים, גרפי ביצועים |
| **בריאות מכשירים** | סטטוס התקני NAS ושרתי Admin |
| **Pods** | טבלת Pod Status ב-Kubernetes |
| **Traces** | מעקב מבוזר (Distributed Tracing) |
| **תורים** | סטטוס תורי Kafka/RabbitMQ |
| **התרעות** | התראות מערכת אחרונות |

### עדכונים בזמן אמת

כאשר החיבור פעיל (SignalR), הנתונים מתעדכנים אוטומטית:
- **כל 5 שניות**: סטטוס שירותים, תורי Kafka, Pods, מטריקות
- **כל 30 שניות**: Traces, אירועים, התרעות, בריאות מכשירים

כאשר החיבור מנותק, המערכת עוברת אוטומטית ל-polling (רענון כל 30 שניות).

### שינויים בניטור (v0.3.0)

**בריאות מכשירים:**
- לשונית "בריאות מכשירים" מציגה כעת נתוני בריאות אמיתיים מכל ההתקנים
- כאשר חיבור SignalR מנותק, המערכת עוברת אוטומטית לשאילתות HTTP כל 15 שניות
- אין יותר קריסות בעקבות פורמט JSON שונה מהשרת

**תורים:**
- לשונית "תורים" מציגה כעת תורי RabbitMQ (תקשורת פנימית) במקום Kafka
- Kafka מוצג רק עבור מקורות נתונים חיצוניים

**Traces:**
- שמות שירותים מקוצרים (למשל: "FileProcessor" במקום "DataProcessing.FileProcessor")
- תזמון spans מוצג יחסית לשורש ה-trace

## טיפול בשגיאות

### סוגי שגיאות

#### 1. שגיאות חיבור

**תסמינים:**
- "לא ניתן להתחבר למקור הנתונים"
- "Connection refused"
- "Authentication failed"

**פתרון:**
1. בדוק את פרטי החיבור (כתובת, נתיב, אישורים)
2. לחץ "בדוק חיבור" בעריכת מקור נתונים
3. ודא שהשרת זמין ונגיש
4. בדוק חומת אש/הרשאות

#### 2. שגיאות אימות

**תסמינים:**
- רשומות מופיעות ב"רשומות לא תקינות"
- הודעה: "Validation failed"

**פתרון:**
1. בדוק את הרשומה ב"רשומות לא תקינות"
2. צפה בשגיאת האימות (איזה שדה כשל)
3. אפשרויות:
   - **ערוך רשומה**: תקן את הערך ושלח מחדש
   - **עדכן Schema**: אם הנתונים תקינים אך Schema מחמיר מדי
   - **התעלם**: סמן כ"התעלם" אם לא רלוונטי

#### 3. שגיאות המרת פורמט

**תסמינים:**
- "Failed to parse file"
- "Unsupported format"
- "Encoding error"

**פתרון:**
1. ודא שפורמט הקובץ תואם להגדרה
2. בדוק קידוד (UTF-8 מומלץ)
3. בעיות CSV: בדוק מפריד, escape characters
4. בעיות Excel: ודא שהגליון הראשון מכיל נתונים

#### 4. שגיאות פלט

**תסמינים:**
- "Failed to write to destination"
- "Topic not found" (Kafka)
- "Permission denied" (Folder)

**פתרון:**
1. ודא שיעד הפלט זמין
2. בדוק הרשאות כתיבה
3. Kafka: ודא ש-Topic קיים
4. תיקייה: ודא שהנתיב קיים והרשאות נכונות

#### 5. שגיאות NAS (חדש בגרסה v0.2.0)

**תסמינים:**
- "PersistentVolume not bound"
- "Mount failed"
- "NFS connection refused"

**פתרון:**
1. בדוק את הסטטוס בלשונית "התקני NAS"
2. ודא ששרת ה-NFS פעיל ונגיש
3. בדוק את כתובת ה-IP והנתיב
4. ודא שיש הרשאות מתאימות ל-export

### צפייה ברשומות לא תקינות

1. לחץ "רשומות לא תקינות" בתפריט
2. רשימת רשומות שנכשלו באימות
3. לכל רשומה:
   - **מקור**: מאיזה מקור נתונים
   - **שגיאה**: מה השגיאה (שדה חסר, ערך לא תקין, וכו')
   - **נתונים**: הנתונים המקוריים
   - **תאריך**: מתי התגלתה השגיאה

**פעולות:**
- **צפה**: הצג פרטים מלאים
- **ערוך**: תקן את הנתונים
- **שלח מחדש**: עבד שוב לאחר תיקון
- **התעלם**: סמן כלא רלוונטי
- **מחק**: הסר מהרשימה

## שאלות נפוצות

### כללי

**ש: האם המערכת תומכת בקבצים דחוסים (ZIP)?**
ת: כן! המערכת תומכת בחילוץ אוטומטי של ארכיונים בפורמטים: ZIP, TAR.GZ, RAR, 7Z. ראה סעיף "הגדרות ארכיון" למידע נוסף.

**ש: מה הגודל המקסימלי של קובץ?**
ת: ברירת מחדל 100MB. ניתן להגדיר ערך שונה בהגדרות מקור הנתונים.

**ש: כמה זמן נשמרים קבצים מעובדים?**
ת: לפי תקופת השמירה שהוגדרה (ברירת מחדל: 30 יום).

### מקורות נתונים

**ש: האם ניתן לעבד אותו קובץ פעמיים?**
ת: לא. המערכת משתמשת ב-deduplication כדי למנוע עיבוד כפול. TTL: 15 דקות.

**ש: מה קורה אם מקור הנתונים לא זמין זמנית?**
ת: המערכת תנסה שוב לפי מדיניות retry (3 ניסיונות, delays: 100ms, 500ms, 1s, 2s, 5s).

**ש: האם ניתן לעבד קבצים היסטוריים?**
ת: כן. הנח קבצים בתיקיית המקור והפעל ידנית (כפתור ברק).

---

### Schema ואימות

**ש: מה קורה לרשומות שלא עוברות אימות?**
ת: תלוי בהגדרת "פעולה בעת שגיאה":
- **המשך עיבוד**: רשומות תקינות ממשיכות, שגויות נשלחות ל"רשומות לא תקינות"
- **הפסק**: כל הקובץ נדחה

**ש: האם ניתן לשנות Schema אחרי שנוצר?**
ת: כן, אבל זה משפיע רק על קבצים עתידיים.

**ש: מה זה "תבנית Regex"?**
ת: ביטוי רגולרי לאימות פורמט. המערכת כוללת עזרת Regex עם תבניות נפוצות.

### ארכיונים

**ש: אילו פורמטי ארכיון נתמכים?**
ת: ZIP, TAR.GZ, RAR, 7Z. המערכת מזהה אוטומטית לפי סיומת או תוכן הקובץ.

**ש: מה קורה אם הארכיון מוגן בסיסמה?**
ת: הזן את הסיסמה בהגדרות מקור הנתונים. אם הסיסמה שגויה, העיבוד ייכשל.

**ש: האם יש הגבלה על גודל הארכיון?**
ת: כן. המערכת כוללת הגנות אבטחה נגד Zip Bomb. גודל מקסימלי מוגדר בהגדרות המערכת.

## טיפים ומומלצות

### בהתחלת השימוש

1. **התחל עם קטגוריות**: הגדר קטגוריות לפני יצירת מקורות נתונים
2. **השתמש בתבניות Schema**: חוסך זמן ומונע שגיאות
3. **בדוק חיבור**: תמיד בדוק חיבור לפני שמירה
4. **התחל בידני**: צור מקור חדש עם תזמון ידני, בדוק שהכל עובד, ואז הפעל תזמון
5. **התחל קטן**: נסה עם קובץ קטן לפני עיבוד המוני

### אופטימיזציה

1. **השתמש ב-Schema**: אימות מונע נתונים שגויים בהמשך
2. **הגדר תקופת שמירה סבירה**: לא יותר ממה שצריך (חוסך מקום)
3. **סנן קבצים**: השתמש בתבנית שם קובץ כדי לעבד רק קבצים רלוונטיים
4. **מעקב אחר שגיאות**: בדוק "רשומות לא תקינות" בקביעות
5. **השתמש במטריקות**: עקוב אחר דשבורד למניעת בעיות

### מה לא לעשות

- **אל תמחק מקור נתונים פעיל בתזמון** (השבת קודם)
- **אל תשנה Schema באמצע עיבוד** (המתן לסיום)
- **אל תשכח לבדוק חיבור** אחרי שינוי הגדרות
- **אל תתעלם משגיאות חוזרות** (בדוק logs ותקן בעיה בשורש)
- **אל תגדיר תזמון תכוף מדי** (יעמיס על המערכת ללא צורך)

## מילון מונחים

| מונח | הסבר |
|------|-------|
| **מקור נתונים (DataSource)** | הגדרה של מקום לאיסוף קבצים ממנו |
| **Schema** | מבנה הנתונים הצפוי וכללי אימות |
| **אימות (Validation)** | בדיקה שהנתונים תואמים ל-Schema |
| **רשומה (Record)** | שורה בקובץ או אובייקט JSON |
| **קטגוריה** | סיווג של מקור נתונים לפי תחום עסקי |
| **תזמון (Schedule)** | מתי המערכת תבדוק קבצים חדשים |
| **יעד פלט (Output Destination)** | לאן לשלוח נתונים מעובדים |
| **NAS** | התקן אחסון ברשת (Network Attached Storage) |
| **NFS** | פרוטוקול שיתוף קבצים (Network File System) |
| **PV/PVC** | משאבי אחסון ב-Kubernetes |
| **deduplication** | מניעת עיבוד כפול של אותו קובץ |
| **Cron Expression** | ביטוי לתזמון מתקדם |
| **Pipeline** | שרשרת העיבוד: גילוי - המרה - אימות - פלט |
| **SignalR** | טכנולוגיית WebSocket לעדכונים בזמן אמת |
| **OTEL** | OpenTelemetry - תקן לאיסוף טלמטריה (logs, traces, metrics) |
| **ניטור (Monitoring)** | מעקב אחר מצב המערכת והשירותים |
| **בריאות מכשיר (Device Health)** | סטטוס זמינות של התקן NAS או שרת Admin |
| **ארכיון (Archive)** | קובץ דחוס המכיל קבצים אחרים (ZIP, TAR.GZ, וכו') |
| **תבנית חילוץ (Extraction Pattern)** | Glob pattern לסינון קבצים בעת חילוץ ארכיון |
| **Zip Bomb** | ארכיון זדוני שמנסה להציף את המערכת בנתונים |
