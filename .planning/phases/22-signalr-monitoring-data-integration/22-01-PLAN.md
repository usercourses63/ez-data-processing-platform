Wait 35 seconds for at least one full broadcast cycle (30s infrastructure + 5s health), then check logs:

```bash
kubectl logs deployment/datasource-management -n ez-platform --tail=100 | grep -i "broadcast\|monitoring\|kubernetes\|prometheus\|kafka\|jaeger\|trace\|infrastructure"
```

**Expected log patterns for SUCCESS (look for these):**
- K8s: `"Infrastructure broadcast"` with non-empty service/pod arrays (NOT `"services":[],"pods":[]`)
- Prometheus: `"MetricsUpdate"` with actual metric values (NOT all zeros)
- Kafka: `"QueueStatusUpdate"` with topic names (NOT `"unknown"` for all)
- Jaeger: `"TraceUpdate"` with trace data (may be empty if no recent processing, but no error logged)
- Pipeline: PipelineEventConsumer registration confirmed (events only flow when files are processed)

**Expected log patterns for FAILURE (investigate these):**
- `"Failed to get pod statuses"` = RBAC still not working
- `"Failed to get Kafka queue statuses"` = Kafka bootstrap DNS issue
- `"Prometheus instant query failed"` = Prometheus endpoint wrong
- `"Failed to get traces"` = Jaeger endpoint wrong

**4. If Kafka bootstrap fails (service DNS mismatch):**

Check actual Kafka service name:
```bash
kubectl get svc -n ez-platform | grep kafka
```

If the service is named `kafka-service` not `kafka`, the ConfigMap `kafka-server` value already handles this correctly (it uses the Helm helper). The `Kafka__Brokers` env var will pick up the correct value. If still failing, check the actual ConfigMap value:
```bash
kubectl get configmap services-config -n ez-platform -o jsonpath='{.data.kafka-server}'
```

**5. If Prometheus business port mismatch:**

Verify port:
```bash
kubectl get svc prometheus-business -n ez-platform -o jsonpath='{.spec.ports[0].port}'
```

If the service port is 9090 (not 9091), update ConfigMap `prometheus-business-endpoint` to use port 9090.

**6. Verify PipelineEventConsumer registration:**

```bash
kubectl logs deployment/datasource-management -n ez-platform --tail=200 | grep -i "consumer\|masstransit\|pipeline"
```

If PipelineEventConsumer is registered but no events flow, this is expected when no files are being processed. The consumer will be verified in Plan 22-02 when we test with real file processing.
