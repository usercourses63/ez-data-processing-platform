Add multi-user CRUD broadcast via SignalR and optimistic locking to DataSource and NAS device controllers.

Purpose: Per locked decisions in CONTEXT.md, when any user performs CRUD operations, all connected clients must receive a SignalR broadcast to refresh their data. Optimistic locking using the existing Version field prevents silent data overwrites. This completes the real-time multi-user experience.

Output: Controllers emit EntityChanged events via MonitoringHub; update endpoints check Version for conflicts (409); frontend invalidates React Query cache on EntityChanged events.

import { useQueryClient } from '@tanstack/react-query';

In the event subscription block (where other `.on()` handlers are registered), add:
```typescript
connection.on('EntityChanged', (data: { EntityType: string; EntityId: string; Action: string; Version: number }) => {
  console.log(`[SignalR] EntityChanged: ${data.EntityType} ${data.EntityId} ${data.Action} v${data.Version}`);

  // Invalidate React Query cache for the changed entity type
  const queryKeyMap: Record<string, string[]> = {
    'DataSource': ['datasources', 'datasource'],
    'NasDevice': ['nasDevices', 'nasdevices'],
    'AdminServer': ['adminservers', 'servers'],
  };

  const keysToInvalidate = queryKeyMap[data.EntityType] || [data.EntityType.toLowerCase()];
  keysToInvalidate.forEach(key => {
    queryClient.invalidateQueries({ queryKey: [key] });
  });
});
```

Also add cleanup for this handler in the disconnect/cleanup section:
```typescript
connection.off('EntityChanged');
```
