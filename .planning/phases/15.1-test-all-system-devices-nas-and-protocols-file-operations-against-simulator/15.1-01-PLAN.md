  <action>
    Create a lightweight REST controller that proxies to IServerConnector methods for any registered AdminServer. This bridges the gap between the connector layer (which has List/Read/Write) and the API layer (which currently only has TestConnection).

    1. **FileOperationRequests.cs** - Create request/response DTOs:
       - `ListFilesRequest { string? Path; string Pattern = "*"; }` (query params or body)
       - `WriteFileRequest { string FilePath; }` (file content as multipart or base64 in body)
       - `FileOperationResponse { bool IsSuccess; string? ErrorMessage; }` wrapping results

    2. **IFileOperationsService.cs** - Service interface:
       - `Task<List<DiscoveredFile>> ListFilesAsync(string serverId, string? path, string pattern, CancellationToken ct)`
       - `Task<byte[]> ReadFileAsync(string serverId, string filePath, CancellationToken ct)`
       - `Task WriteFileAsync(string serverId, string filePath, byte[] content, CancellationToken ct)`

    3. **FileOperationsService.cs** - Implementation:
       - Inject `IServerService` (existing) to resolve AdminServer by ID
       - Inject `IConnectorFactory` to get the right connector
       - Cast `IDataSourceConnector` to `IServerConnector` (throw if not supported)
       - For credentials: pass `null` for now (file-simulator doesn't need K8s secrets; credentials come from TypeSpecificConfig). If server has CredentialSecretRef, create ServerCredentials from it if possible, otherwise pass null.
       - Each method: lookup server -> get connector -> cast to IServerConnector -> call method

    4. **FileOperationsController.cs** - REST endpoints:
       - Route: `api/v1/file-operations`
       - `POST api/v1/file-operations/{serverId}/list` - accepts `{ Path?: string, Pattern?: string }`, returns `List<DiscoveredFile>`
       - `POST api/v1/file-operations/{serverId}/read` - accepts `{ FilePath: string }`, returns file bytes as `application/octet-stream`
       - `POST api/v1/file-operations/{serverId}/write` - accepts `{ FilePath: string, Content: string }` where Content is base64-encoded bytes, returns success/failure
       - Add proper error handling: 404 if server not found, 400 if connector doesn't support IServerConnector, 500 for operation failures
       - Use PascalCase for all request properties (backend convention: PropertyNamingPolicy = null)

    5. **Program.cs** - Register the new service:
       - Add `builder.Services.AddScoped<IFileOperationsService, FileOperationsService>();`
       - Ensure IConnectorFactory is already registered (it should be via Shared Configuration)

    IMPORTANT: Do NOT modify existing controllers or services. This is purely additive.
    IMPORTANT: Use PascalCase properties in request models (backend convention).
    IMPORTANT: For the KafkaConnector which only implements IDataSourceConnector (not IServerConnector), the cast will fail. Return 400 with message "Server type '{type}' does not support file operations" for Kafka write specifically. For Kafka list/read, KafkaConnector does NOT implement IServerConnector at all, so return 400 for all file operations on Kafka servers with a clear message.
