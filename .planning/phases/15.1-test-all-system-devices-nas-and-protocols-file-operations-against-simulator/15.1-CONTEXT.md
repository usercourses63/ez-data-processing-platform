# Phase 15.1: Test All System Devices (NAS and Protocols) File Operations Against Simulator - Context

**Gathered:** 2026-02-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Validate that all device types and protocol-based file operations work correctly against the file-simulator service. This is a pure testing/validation phase — all connectors already exist. No new connector code. Two scenarios: static devices (pre-existing) and dynamic devices (created via simulator API → EZ UI → file operations).

</domain>

<decisions>
## Implementation Decisions

### Protocol Coverage
- Full protocol list: Kafka (local cluster), Kafka (simulator), FTP, SFTP, HTTP, S3, HTTP WebDAV, NAS devices (NFS mount)
- 8 protocols total
- All connectors already implemented in src/Services/Shared/Connectors/

### File Format Coverage
- All supported formats: CSV, JSON, XML, Excel
- Full matrix: every protocol × every format combination
- Static test data files pre-created in the repo (not generated dynamically)

### File Operations
- Read + Write + List operations per protocol
- Protocol-appropriate operations (not every protocol supports all ops equally)

### Test Scenarios
- **Scenario A (Static):** Test file operations against pre-existing/static devices on the simulator
- **Scenario B (Dynamic):** Create new servers via simulator REST API → Add servers/NAS devices through EZ System Settings UI (Playwright) including provisioning → Test all file operations on newly created devices
- Both scenarios run the same file operation matrix

### Execution Framework
- Playwright E2E test suite in src/Frontend/tests/e2e/
- One test file per protocol (ftp.spec.ts, sftp.spec.ts, etc.)
- Device creation: through EZ UI via Playwright (full user workflow)
- File operations: through backend API calls (via Playwright request context)
- Cleanup in afterAll — delete created devices/servers after tests

### Environment
- Live minikube clusters required (EZ cluster + file-simulator cluster)
- Assume file-simulator cluster already running at 172.17.89.141
- Assume EZ cluster already running at current minikube IP
- NodePort + direct Hyper-V IPs for cross-cluster communication
- Dynamic servers created via file-simulator REST API before Playwright UI flows

### Pass/Fail Criteria
- Strict: all operations must succeed — any failure = protocol fails
- Playwright HTML report for CI
- Custom markdown summary report with protocol × format matrix showing pass/fail per combo

### Claude's Discretion
- Per-protocol operation mapping (which ops to test per protocol based on capabilities)
- Failure diagnostic capture level (screenshots, traces, API response bodies)
- Markdown summary report location (test-results/ or .planning/ phase dir)
- Test file organization details (helpers, fixtures, shared utilities)

</decisions>

<specifics>
## Specific Ideas

- Tests should create dynamic servers via simulator API first, then use the EZ "Add Server" and "Add NAS Device" dialogs in System Settings to register them
- NAS devices should go through full provisioning flow in the UI
- The protocol × format matrix report should make it immediately clear which combinations work and which don't
- Port-forward approach known to hang with Hyper-V — NodePort is the reliable path

</specifics>
