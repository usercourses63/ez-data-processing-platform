<objective>
Establish the backend credential contract for the AdminServer S3 path: the PascalCase key set in `TypeSpecificConfig`, encrypt-at-rest of `SecretKey`, and decrypt-on-read so the connection-establish flow receives real keys. This is the foundation every other plan builds on — it freezes the exact key names (`AccessKey`, `SecretKey`, `Bucket`, `Region`, `ForcePathStyle`, `UseHttp`, optional `SessionToken`/`Endpoint`) and the secret-at-rest mechanism.

Purpose: Without keys reaching `S3Connector.CreateS3Client`, the AWS SDK falls through to `FallbackCredentialsFactory` and throws "IAM credentials is missing" (SC-05). Without encrypt-at-rest the secret sits plaintext in Mongo (SC-04). This plan fixes both at the source.

Output: `ServerCredentialProtector` (AES field encryption), encryption wired into `ServersController` create/update, `ServerCredentials.FromBsonDocument` decrypt-aware, and confirmation that the PascalCase contract matches what `S3ConnectorTests.cs` already proves.
</objective>

    - src/Services/Shared/Services/ICredentialResolver.cs (ServerCredentials, FromBsonDocument, redacted ToString — the existing key contract and the redaction helper to reuse)

    - Directory.Build.props (target framework, nullable settings)
  </read_first>
  <behavior>
    - Protect(plaintext) returns a non-empty string that is NOT equal to plaintext and is prefixed with a discriminator (e.g. "enc:v1:") so encrypted values are detectable.
    - Unprotect(Protect(x)) == x (round-trip) for arbitrary UTF-8 secrets including empty and 64-char keys.
    - Unprotect on a value WITHOUT the "enc:v1:" prefix returns the input unchanged (back-compat: legacy plaintext secrets read through transparently).
    - IsProtected("enc:v1:...") == true; IsProtected("minioadmin123") == false.
    - The AES key is read from configuration key Credentials:FieldEncryptionKey (env Credentials__FieldEncryptionKey); if absent in non-production the protector uses a documented dev fallback key and logs a single warning (never logs the key).
  </behavior>
  <action>
    Create `ServerCredentialProtector` in `DataProcessing.Shared.Services` with `Protect(string)`, `Unprotect(string)`, `IsProtected(string)`. Use `System.Security.Cryptography.Aes` (AES-256-CBC + random IV prepended to ciphertext, Base64-encoded, with the "enc:v1:" discriminator) — do NOT hand-roll a cipher, use the framework primitive (Don't-Hand-Roll, RESEARCH). Read the key from `IConfiguration` `Credentials:FieldEncryptionKey`; derive a 32-byte key via SHA-256 of the configured secret. Per D-A3 (secret-at-rest = field-level encryption of SecretKey in TypeSpecificConfig), this is the chosen mechanism over forcing the K8s-Secret path. Add a static helper on ServerCredentials (or a method on the protector) — `DecryptSecretInPlace(BsonDocument, ServerCredentialProtector)` — that, if `SecretKey` is present and protected, replaces it with the decrypted value before `FromBsonDocument` reads it. Reuse the existing redacted `ToString()` for any log line. Do NOT add new packages (RESEARCH: no new dependencies).
  </action>
  <verify>
    <automated>dotnet test tests/Shared.Tests --filter "FullyQualifiedName~ServerCredentialProtector" 2>&1 | Select-String -Pattern "Passed|Failed|error"</automated>
  </verify>
  <done>Protector round-trips, prefixes ciphertext with "enc:v1:", reads legacy plaintext transparently, and the Shared.Tests protector suite exits 0.</done>
