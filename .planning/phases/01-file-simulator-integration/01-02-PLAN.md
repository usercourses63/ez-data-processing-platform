# File-Simulator Integration Guide

## Overview

File-simulator provides realistic protocol servers (FTP, SFTP, S3, SMB, NFS, HTTP) for testing
EZ Platform's file I/O operations. It runs in a separate Minikube profile and communicates
with EZ Platform via NodePort services.

**Important:** This guide covers infrastructure setup and connectivity verification only.
Protocol integration tests (verifying connectors work correctly) are in Phase 3.

## Prerequisites

- Minikube with Hyper-V driver (for file-simulator)
- Minikube with Docker driver (for EZ Platform)
- Helm 3.x
- PowerShell 7.x (for verification scripts)
- file-simulator-suite repo: C:\Users\UserC\source\repos\file-simulator-suite

## Quick Start

### 1. Start file-simulator cluster

minikube start --profile file-simulator --driver=hyperv --memory=8192 --cpus=4 \
  --mount --mount-string="C:\simulator-data:/mnt/simulator-data"

### 2. Deploy file-simulator

cd C:\Users\UserC\source\repos\file-simulator-suite
helm upgrade --install file-sim .\helm-chart\file-simulator \
  --kube-context=file-simulator \
  --namespace file-simulator \
  --create-namespace

### 3. Apply NFS fix (required)

kubectl --context=file-simulator patch deployment file-sim-file-simulator-nas \
  -n file-simulator --patch-file nfs-fix-patch.yaml

### 4. Verify connectivity

cd C:\Users\UserC\source\repos\EZ
.\scripts\verify-file-simulator.ps1 -Apply

## ConfigMap Configuration

The file-simulator-config ConfigMap contains all protocol endpoints.
Located at: k8s/configmaps/file-simulator-config.yaml

Key environment variables:
- FileAccess__Ftp__Host - FTP server hostname
- FileAccess__Sftp__Host - SFTP server hostname
- FileAccess__S3__Endpoint - S3-compatible endpoint URL
- FileAccess__Http__BaseUrl - HTTP server URL
- FileSimulator__Enabled - Feature flag for file-simulator mode

## Verification

Run the verification script to test all endpoints:

.\scripts\verify-file-simulator.ps1 -TestOnly  # Test without applying
.\scripts\verify-file-simulator.ps1 -Apply     # Test and apply ConfigMap

Expected output:
  FTP        : OK - FTP Server
  SFTP       : OK - SFTP Server
  S3/MinIO   : OK - S3-compatible API
  HTTP       : OK - HTTP Server
  WebDAV     : OK - WebDAV Server
  S3 Health  : OK - MinIO responding
  Results: 6/6 tests passed

## Protocol Reference

|----------|----------|----------|----------|
| FTP | 30021 | ftpuser | ftppass123 |
| SFTP | 30022 | sftpuser | sftppass123 |
| S3/MinIO | 30900 | minioadmin | minioadmin123 |
| HTTP | 30088 | httpuser | httppass123 |
| WebDAV | 30089 | httpuser | httppass123 |

| NAS Output 3 | 32156 | Output server 3 |
| NAS Backup | 32153 | Backup server |

## Troubleshooting

### Issue: Connection refused

**Cause:** file-simulator cluster not running or pods not ready

**Solution:**
1. Check cluster: minikube status -p file-simulator
2. Check pods: kubectl --context=file-simulator get pods -n file-simulator
3. Wait for pods: kubectl --context=file-simulator wait --for=condition=ready pod -l app=file-simulator -n file-simulator --timeout=300s

### Issue: IP address changed

**Cause:** Minikube assigns dynamic IPs; file-simulator IP changed after restart

**Solution:**
1. Re-run verification: .\scripts\verify-file-simulator.ps1 -Apply
2. Restart services: kubectl --context=minikube rollout restart deployment -n ez-platform

### Issue: SMB not working

**Cause:** SMB requires standard port 445, not NodePort

**Solution:**
1. Run tunnel: minikube tunnel -p file-simulator (in separate terminal)
2. Use LoadBalancer IP for SMB connections
3. See RESEARCH.md for SMB-specific configuration

### Issue: NFS files not visible

**Cause:** Init container only syncs at pod start

**Solution:**
1. Place test files in C:\simulator-data\nas-input-1\
2. Restart NAS pod: kubectl --context=file-simulator delete pod -n file-simulator -l nas-server=nas-input-1
3. Wait 30 seconds for sync
