    - CRITICAL: Use PascalCase property names to match backend JSON serialization (`PropertyNamingPolicy = null`). This is a known pitfall (commit 18610e0).
    - `DeviceHealthStatusResponse`: `TotalDevices: number`, `HealthyCount: number`, `DegradedCount: number`, `DownCount: number`, `DisabledCount: number`, `NasDevices: DeviceHealthInfo[]`, `AdminServers: DeviceHealthInfo[]`
    - `DeviceHealthInfo`: `DeviceId: string`, `DeviceName: string`, `DeviceType: string`, `DeviceSubType?: string`, `Role: string`, `Status: string` (one of "Healthy" | "Degraded" | "Down" | "Disabled"), `LatencyMs?: number`, `LastCheckTime?: string`, `ErrorMessage?: string`, `UptimePercentage24h: number`, `IsActive: boolean`
    - Export type `DeviceHealthStatus = 'Healthy' | 'Degraded' | 'Down' | 'Disabled'` for type safety

    **2. Create API client** (`src/Frontend/src/services/health-status-api-client.ts`):
    - Follow existing pattern from `nas-devices-api-client.ts` and `servers-api-client.ts`
    - `const API_BASE_URL = '';` (empty string, proxied through Vite/nginx)
    - `getDeviceHealthStatus()`: `fetch(API_BASE_URL + '/api/v1/health-status')`, parse as `DeviceHealthStatusResponse`, throw on non-ok response
    - `useDeviceHealthStatus()` custom hook using `useQuery` from `@tanstack/react-query`:
      ```
      queryKey: ['device-health-status'],
      queryFn: getDeviceHealthStatus,
      refetchInterval: 15000,       // 15-second polling per user decision
      refetchIntervalInBackground: false,  // Only when tab is visible
      staleTime: 10000,             // Data considered fresh for 10 seconds
      ```
    - Export both the raw function and the hook
