    **3. Create IDeviceHealthService interface** (`src/Services/DataSourceManagementService/Services/IDeviceHealthService.cs`):
    - `Task RunHealthChecksAsync(CancellationToken ct)` -- run all health checks
    - `Task<DeviceHealthStatusResponse> GetHealthStatusAsync(CancellationToken ct)` -- get aggregated status for API

    **4. Create DeviceHealthService** (`src/Services/DataSourceManagementService/Services/DeviceHealthService.cs`):
    - Constructor DI: `INasDeviceService`, `IServerService`, `ILogger<DeviceHealthService>`
    - Private `ConcurrentDictionary<string, int> _consecutiveFailures` for failure tracking
    - **RunHealthChecksAsync:**
      - Fetch all NAS devices via `INasDeviceService.GetAllNasDevicesAsync()`
      - Fetch all AdminServers via `IServerService.GetAllServersAsync()`
      - Skip NAS devices where `!IsActive || IsDeleted` or `!IsProvisioned` (not provisioned ones are shown as Disabled)
      - Skip AdminServers where `!IsActive || IsDeleted`
      - Run health checks in parallel using `Task.WhenAll` with a per-device 5-second timeout via `CancellationTokenSource(TimeSpan.FromSeconds(5))`
      - **NAS health check:** Use `INasDeviceService.TestConnectionAsync(device.ID)` which checks PVC binding status. Measure latency with Stopwatch. If latency > 2000ms, mark as Degraded.
      - **AdminServer health check:** Use `IServerService.TestConnectionAsync(server.ID)` which tests protocol-specific connectivity via IConnectorFactory. If latency > 5000ms, mark as Degraded.
      - **Consecutive failure tracking:** On failure, increment `_consecutiveFailures[deviceId]`. 0 failures = Healthy, 1-2 = Degraded, 3+ = Down. On success, remove from dictionary (auto-recover to Healthy).
      - **Combined status:** Take the worse of latency-based and failure-based status (e.g., if latency says Degraded and failures say Healthy, use Degraded).
      - Persist each check result as a new `DeviceHealthCheckResult` via `DB.SaveAsync()`
      - Log each check: `"Health check for {DeviceName}: {Status} ({LatencyMs}ms)"`
    - **GetHealthStatusAsync:**
      - Fetch latest health check result per device: query `DeviceHealthCheckResult` grouped by DeviceId, take the one with max CheckedAt
      - Fetch all NAS devices and AdminServers for device metadata (Name, Role, Type, IsActive, IsProvisioned)
      - For disabled/unprovisioned devices, return `Status = "Disabled"`, no latency
      - Calculate 24h uptime using `CalculateUptimePercentageAsync(deviceId, TimeSpan.FromHours(24))`
      - Build `DeviceHealthStatusResponse` with summary counts and device lists grouped by type
    - **CalculateUptimePercentageAsync:** Query all checks for device in last 24h, compute `successCount / totalCount * 100`, round to 1 decimal. Return 0 if no checks.
    - Run an initial health check round on startup by making the service also implement `IHostedService` with `StartAsync` calling `RunHealthChecksAsync` once after a 5-second delay.

    **5. Create DeviceHealthCheckJob** (`src/Services/DataSourceManagementService/Jobs/DeviceHealthCheckJob.cs`):

    - Constructor DI: `IDeviceHealthService`, `ILogger<DeviceHealthCheckJob>`
    - `Execute`: call `_healthService.RunHealthChecksAsync(context.CancellationToken)`
    - Include ActivitySource tracing and structured logging

      ```
      builder.Services.AddQuartz(q =>
      {
          q.UseInMemoryStore();
          var jobKey = new JobKey("DeviceHealthCheck");
          q.AddJob<DeviceHealthCheckJob>(opts => opts.WithIdentity(jobKey));
          q.AddTrigger(opts => opts
              .ForJob(jobKey)
              .WithIdentity("DeviceHealthCheck-trigger")
              .WithSimpleSchedule(x => x
                  .WithIntervalInSeconds(30)
                  .RepeatForever()));
      });
      builder.Services.AddQuartzHostedService(q => q.WaitForJobsToComplete = true);
      ```
