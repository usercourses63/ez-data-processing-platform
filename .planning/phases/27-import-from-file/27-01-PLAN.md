3. Create `src/Frontend/src/utils/fileAnalyzer/encodingDetector.ts`:
   - Export `detectEncoding(buffer: Uint8Array): string`
   - Check BOM first: EF BB BF = UTF-8, FF FE = UTF-16LE, FE FF = UTF-16BE
   - Use jschardet on first 4096 bytes for content-based detection
   - Map jschardet results to project encoding names: 'UTF-8', 'Windows-1255', 'ISO-8859-8', 'UTF-16'
   - Default to 'UTF-8' if detection confidence < 0.5

4. Create `src/Frontend/src/utils/fileAnalyzer/schemaInferrer.ts`:
   - Export `inferTypeFromValue(value: string): 'string' | 'integer' | 'number' | 'boolean'`
     - Empty string -> 'string'
     - Boolean: true/false/yes/no/0/1 (case insensitive) -> 'boolean'
     - Integer: /^-?\d+$/ -> 'integer'
     - Number: /^-?\d+\.\d+$/ -> 'number'
     - Default -> 'string'
   - Export `inferColumnType(values: string[]): InferredType`
     - Use majority-rules with type hierarchy: any string -> 'string', any number mixed with integer -> 'number', all boolean -> 'boolean', all integer -> 'integer'
     - Sample at least 20 rows (or all if fewer)
   - Export `generateJsonSchema(fieldNames: string[], rows: Record<string, string>[], applySuggestions: boolean): object`
     - Returns JSON Schema 2020-12 with `$schema`, `type: 'object'`, `properties`, `required`, `additionalProperties: false`
     - Each property has inferred `type`
     - When `applySuggestions=true`, call `suggestConstraintsForField()` and `applySuggestionsToSchema()` from `schemaAutoSuggest.ts` for IMPORT-04
     - Mark field as `required` if no empty values in sample data
   - Export `buildFieldTypes(fieldNames: string[], rows: Record<string, string>[]): Record<string, string>` -- returns field -> type map for preview display (D-10)
   - Export `buildFieldConstraints(fieldNames: string[]): Record<string, any>` -- returns field -> constraint summary from schemaAutoSuggest for preview display (D-10)

5. Create `src/Frontend/src/utils/fileAnalyzer/patternInferrer.ts`:
   - Export `inferFilePattern(filename: string): string`
     - Strip extension, replace date-like patterns (YYYY-MM-DD, YYYYMMDD, YYYY) with `*`, replace remaining 2+ digit sequences with `*`, collapse multiple wildcards, re-add extension
   - Export `inferDatasourceName(filename: string): string`
     - Strip extension from filename: `sales_2026.csv` -> `sales_2026`

1. Create `csvAnalyzer.ts`:
   - Export `detectHasHeaders(rows: string[][]): boolean`
     - Per D-12: Compare first row type distribution vs data rows. If first row has significantly fewer numeric/boolean values than average data row -> headers. If < 2 rows, assume headers.
   - Export `analyzeCsv(text: string, filename: string, encoding: string): ImportData`
     - Parse with PapaParse: `Papa.parse(text, { header: false, preview: 21, dynamicTyping: false, skipEmptyLines: true })`
     - Get `detectedDelimiter` from `rawResult.meta.delimiter` (PapaParse auto-detects)
     - Run `detectHasHeaders` on raw rows
     - If headers: first row = fieldNames, rest = dataRows
     - If no headers: generate `field_1, field_2, ... field_N` as fieldNames per D-15/IMPORT-03
     - Count total rows with a second `Papa.parse` using `step` callback (subtract 1 if headers)
     - Build `previewRows` as array of objects (first 5 data rows mapped to fieldNames) per D-09
     - Call `generateJsonSchema(fieldNames, dataRowsAsObjects, true)` for schema with auto-suggest per IMPORT-02/IMPORT-04
     - Call `buildFieldTypes` and `buildFieldConstraints` for preview display per D-10
     - Return full `ImportData` with `inferFilePattern(filename)` and `inferDatasourceName(filename)`

2. Create `jsonAnalyzer.ts`:
   - Export `analyzeJson(text: string, filename: string, encoding: string): ImportData`
     - `JSON.parse(text)` -- if result is array, use first element as record template; if object, wrap in array
     - Extract field names from first record's keys (handle nested objects by flattening top-level)
     - Build `previewRows` (first 5 elements) per D-09
     - Infer schema using `generateJsonSchema` -- for JSON, values are already typed (use `typeof` for type detection instead of string parsing)
     - Generate schema with `$schema: 'https://json-schema.org/draft/2020-12/schema'`
     - Return full `ImportData` with `fileType: 'JSON'`

3. Create `xmlAnalyzer.ts`:
   - Export `analyzeXml(text: string, filename: string, encoding: string): ImportData`
     - Use `new DOMParser().parseFromString(text, 'text/xml')`
     - Check for `parsererror` element -- throw descriptive error if found
     - Find repeating record elements (root's direct children)
     - Extract field names from first record's child elements
     - Build `previewRows` from first 5 records (child tagName -> textContent mapping) per D-09
     - Infer schema from text content values using `generateJsonSchema`
   - Export `buildXmlTreeData(element: Element): TreeDataNode[]`
     - Recursive walk: each element -> `{ title: tagName, key: unique_key, children: [...] }`
     - Leaf nodes (no children): `title: 'tagName: textContent'`, `isLeaf: true`
     - Set `xmlTreeData` on the returned ImportData for D-11
     - Return full `ImportData` with `fileType: 'XML'`

4. Create `excelAnalyzer.ts`:
   - Export `analyzeExcel(buffer: ArrayBuffer, filename: string): ImportData`
     - Use `XLSX.read(buffer, { type: 'array', cellDates: true })`
     - Take first sheet: `workbook.SheetNames[0]`
     - Use `XLSX.utils.sheet_to_json(sheet, { raw: true })` for typed values per Research Pitfall 5
     - Extract field names from first row keys
     - Build `previewRows` (first 5 rows) per D-09
     - Generate schema using `generateJsonSchema` -- note Excel values may already be typed, convert to strings for the inferrer or use a typed variant
     - Return full `ImportData` with `fileType: 'Excel'`, `encoding: 'UTF-8'` (Excel is binary), `hasHeaders: true` (SheetJS default)

5. Create `index.ts` -- the main orchestrator:
   - Export `analyzeFile(file: File): Promise<ImportData>`
   - 10MB file size limit with descriptive error (Claude's Discretion)
   - Determine extension from `file.name` (handle `.tar.gz` as special case)
   - If archive extension (`.zip`, `.tar.gz`, `.rar`, `.7z`): throw with message directing to archive flow (handled separately in Plan 27-02)
   - For data files: read `file.arrayBuffer()`, detect encoding, decode with `TextDecoder`, delegate to format-specific analyzer
   - For `.xlsx`: pass `ArrayBuffer` directly to `analyzeExcel` (no text decoding)
   - Export `isArchiveExtension(ext: string): boolean` and `isSupportedExtension(ext: string): boolean` for use by upload component
   - Export `getFileExtension(filename: string): string` that handles `.tar.gz`
   - Re-export `ImportData` type and key functions from sub-modules
