  <action>
Create `tools/verify-otel.ps1` — a PowerShell script that verifies OTEL signal presence for all deployed microservices.

**Service registry (8 deployed services):**
| OTEL Service Name | K8s Deployment |
|---|---|
| DataProcessing.DataSourceManagement | datasource-management |
| DataProcessing.Validation | validation |
| DataProcessing.FileProcessor | fileprocessor |
| DataProcessing.FileDiscovery | filediscovery |
| DataProcessing.Scheduling | scheduling |
| DataProcessing.Output | output |
| DataProcessing.MetricsConfiguration | metrics-configuration |
| DataProcessing.InvalidRecords | invalidrecords |

Note: DataSourceChatService is excluded — no k8s deployment exists. Script should print a note about this exclusion.

**Endpoints (via port-forward):**
- Elasticsearch: `http://localhost:9200`
- Jaeger: `http://localhost:16686`
- Prometheus System: `http://localhost:9090`
- Prometheus Business: `http://localhost:9091`

**Log check (OTEL-01):**
Query `POST http://localhost:9200/dataprocessing-logs*/_search` with a bool/should query matching the service name across multiple possible field names (`resource.service.name`, `Resource.service.name`, `service.name`). Size 1, just confirm hits > 0. Wrap in try/catch — if Elasticsearch is unreachable or index doesn't exist, mark as FAIL with error note.

**Trace check (OTEL-02):**
1. `GET http://localhost:16686/api/services` to get all services reporting traces
2. Check if the OTEL service name exists in the services list
3. If found, optionally verify at least one trace exists via `GET http://localhost:16686/api/traces?service={name}&limit=1&lookback=72h`
Mark as PASS if service has traces, FAIL otherwise. Wrap in try/catch.

**Metric check (OTEL-03):**
Query both Prometheus instances:
- System: `GET http://localhost:9090/api/v1/query?query={service_name="DataProcessing.X"}`
- Business: `GET http://localhost:9091/api/v1/query?query={service_name="DataProcessing.X"}`
PASS if either instance returns results. Wrap in try/catch. If the `service_name` label yields no results, also try `exported_service_name` and `service` labels as fallbacks (exact label name depends on OTEL Collector resource-to-telemetry conversion at runtime).

**Output format:**
Print a colored terminal table using `Write-Host -ForegroundColor`:
```
=== OTEL Verification Results ===
Note: DataSourceChatService excluded (no k8s deployment)

Service                                   Logs     Traces   Metrics
------------------------------------------------------------------------
DataProcessing.DataSourceManagement       PASS     PASS     PASS
DataProcessing.Validation                 PASS     PASS     PASS
...

Summary: 24/24 checks passed (8 services x 3 signals)
```

Use Green for PASS, Red for FAIL. Print summary count at end.

**Exit code:** Exit 0 if all checks pass, exit 1 if any fail.

**Script style:** Match existing project scripts (see `scripts/start-port-forwards.ps1` for PowerShell conventions). One-shot, no persistence, no parameters needed. Rerunnable — just execute again after fixes.
