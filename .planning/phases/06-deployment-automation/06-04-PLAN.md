  <files>release-package/helm/ez-platform-ocp/templates/routes/docs-route.yaml</files>
  <action>
Update the OCP Route for docs to serve at the /docs path with proper path rewriting.

Read the existing `release-package/helm/ez-platform-ocp/templates/routes/docs-route.yaml` and update to include path-based routing.

The Route should:
- Match requests to /docs path
- Forward to ezplatform-docs service
- Use edge TLS termination
- Work with Docusaurus baseUrl: '/docs/'

Update to:

```yaml
{{- if and .Values.ocp.enabled .Values.ocp.routes.enabled .Values.services.docs.enabled }}
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: docs
  namespace: {{ .Values.global.namespace }}
  labels:
    app.kubernetes.io/name: ezplatform-docs
    app.kubernetes.io/instance: {{ .Release.Name }}
    app.kubernetes.io/component: documentation
  annotations:
    haproxy.router.openshift.io/rewrite-target: /docs
spec:
  host: {{ .Values.ocp.domain }}
  path: /docs
  to:
    kind: Service
    name: ezplatform-docs
    weight: 100
  port:
    targetPort: 8080
  tls:
    termination: {{ .Values.ocp.routes.tls.termination | default "edge" }}
    insecureEdgeTerminationPolicy: Redirect
  wildcardPolicy: None
{{- end }}
```

Key aspects:
- `path: /docs` - Only routes /docs/* requests to this service
- `haproxy.router.openshift.io/rewrite-target: /docs` - Keeps path intact for Docusaurus
- Shares host with frontend route (same domain, different path)

Note: Since Docusaurus has baseUrl: '/docs/', the path is preserved and Docusaurus handles it correctly.

Read the existing `helm/ez-platform/templates/ingress/ez-platform-ingress.yaml` and add a /docs path rule.

The Ingress should include both frontend (/) and docs (/docs) paths:

```yaml
{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ez-platform-ingress
  namespace: {{ .Values.global.namespace }}
  labels:
    app.kubernetes.io/name: ez-platform-ingress
    app.kubernetes.io/instance: {{ .Release.Name }}
  annotations:
    {{- if .Values.ingress.className }}
    kubernetes.io/ingress.class: {{ .Values.ingress.className }}
    {{- end }}
    {{- with .Values.ingress.annotations }}
    {{- toYaml . | nindent 4 }}
    {{- end }}
spec:
  {{- if .Values.ingress.className }}
  ingressClassName: {{ .Values.ingress.className }}
  {{- end }}
  {{- if .Values.ingress.tls.enabled }}
  tls:
    - hosts:
        - {{ .Values.ingress.host }}
      secretName: {{ .Values.ingress.tls.secretName }}
  {{- end }}
  rules:
    - host: {{ .Values.ingress.host }}
      http:
        paths:
          # Docusaurus documentation at /docs
          {{- if .Values.services.docs.enabled }}
          - path: /docs
            pathType: Prefix
            backend:
              service:
                name: ezplatform-docs
                port:
                  number: 8080
          {{- end }}
          # API routes
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: datasource-management
                port:
                  number: 5001
          # Frontend (catch-all, must be last)
          {{- if .Values.services.frontend.enabled }}
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend
                port:
                  number: 8080
          {{- end }}
{{- end }}
```

Important:
- /docs path rule must come BEFORE the / catch-all rule
- pathType: Prefix ensures /docs/* all route to docs service
- Service name must match the K8s service created for docs

# Documentation Update Workflow

This guide documents the process for updating the Docusaurus documentation portal before each release.

## Overview

EZ Platform uses a dual documentation approach:
- **GSD (.planning/)**: Source of truth for project planning, architecture, and development
- **Docusaurus**: User-facing documentation portal deployed at /docs

Before each release, relevant GSD content is synchronized to Docusaurus.

## Documentation Structure

### Source (GSD)

```
.planning/
├── PROJECT.md           # Project overview
├── ROADMAP.md           # Phase roadmap
├── STATE.md             # Current state
├── codebase/            # Architecture docs
│   ├── ARCHITECTURE.md
│   ├── STACK.md
│   └── CONVENTIONS.md
└── phases/              # Phase execution docs
```

### Target (Docusaurus)

```
release-package/docs-docusaurus/
├── docs/
│   ├── intro.md                 # Welcome page
│   ├── getting-started/         # Quick start guides
│   ├── architecture/            # System architecture
│   ├── deployment/              # Deployment guides

│   └── user-guide/              # End-user documentation
│       ├── he/                  # Hebrew translations
│       └── en/                  # English (default)
├── docusaurus.config.js         # Site configuration
├── sidebars.js                  # Navigation structure
└── src/
    └── css/
        └── custom.css           # Styling
```

## Content Guidelines

### Markdown Format

Docusaurus uses standard Markdown with frontmatter:

```markdown
---
sidebar_position: 1
title: Getting Started
description: Quick start guide for EZ Platform
---

# Getting Started

Content here...
```

### Internal Links

Use relative paths for internal links:

```markdown
<!-- Good -->
[Architecture](./architecture/overview.md)
[Deployment](../deployment/ocp.md)

<!-- Bad -->
[Architecture](/docs/architecture/overview)  # Absolute paths break in dev
```

### Images

Place images in `static/img/` and reference:

```markdown
![Architecture Diagram](/img/architecture.png)
```

### Code Blocks

Use language hints for syntax highlighting:

````markdown
```yaml
# Kubernetes manifest
apiVersion: v1
kind: Service
```
