Create ServerMappingService.cs:
- MapToAdminServer(SimulatorServer server, SimulatorConnectionInfo connInfo) - creates AdminServer entity
  - Protocol mapping: FTP->ftp, SFTP->sftp, HTTP->http, Kafka->kafka, S3->s3
  - Direction: parse from server name (contains "input" -> Input, "output" -> Output, else Both)
  - Host/Port from connInfo protocol-specific section (Ftp.Host, Sftp.Port, etc.)
  - TypeSpecificConfig BsonDocument with credentials from RESEARCH.md (ftpuser/ftppass123, etc.)
  - CredentialSecretRef: ez-platform/file-simulator-{protocol}-creds pattern
  - Set IsActive = server.IsHealthy

- MapToNasDevice(SimulatorServer server, SimulatorConnectionInfo connInfo) - creates NasDevice entity
  - Find matching NAS info from connInfo.Nas list by server.Name
  - Set Role based on name: "input" -> Input, "output" -> Output, "backup" -> Backup, else Both
  - Set Host, Port, ExportPath from NasInfo
  - Set StorageCapacity = "10Gi" (default)
  - Set IsPvCreated = false, IsPvcBound = false (will be provisioned separately)
  - Set IsActive = server.IsHealthy

Create NasDeviceGenerator.cs:
- Constructor takes Random, ServerMappingService, and list of SimulatorServer + SimulatorConnectionInfo
- GenerateAsync() iterates servers where Protocol is "NFS" or "NAS"
- Uses ServerMappingService.MapToNasDevice for each
- Saves to MongoDB via SaveAsync()
- Console output: "  [check] Created NasDevice: {Name} ({Role})"

- SeedFromSimulatorAsync(bool createDynamic, CancellationToken ct):
  1. Check simulator health via EnsureHealthyAsync(), fail fast if not reachable
  2. Clean slate: DB.DeleteAsync&lt;AdminServer&gt;(_ => true), DB.DeleteAsync&lt;NasDevice&gt;(_ => true)
  3. If createDynamic, call CreateNasServerAsync for input/output servers (optional - skip if API doesn't exist)
  4. GetServersAsync() to discover all servers
  5. GetConnectionInfoAsync() for connection details
  6. For each server: if Protocol is NFS/NAS -> MapToNasDevice and save; else -> MapToAdminServer and save
  7. Log summary: "{N} AdminServers, {M} NasDevices seeded from simulator"

Update Program.cs:
- Parse new CLI arguments:

  - --use-simulator (enables simulator seeding mode, otherwise use static generators)
- Load appsettings.json using ConfigurationBuilder
- If --use-simulator flag present:
  - Create HttpClient with Polly retry policy
  - Create FileSimulatorClient, ServerMappingService, SimulatorSeederService
  - Call SeedFromSimulatorAsync with createDynamic based on --create-servers flag
  - Skip AdminServerGenerator.GenerateAsync() step (replaced by simulator seeding)
- If --use-simulator not present:
  - Keep existing behavior with static AdminServerGenerator
- Console output: "Mode: SIMULATOR" or "Mode: STATIC"
