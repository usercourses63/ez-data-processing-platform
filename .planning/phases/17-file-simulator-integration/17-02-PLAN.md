Since FileGeneratorService only generates CSV and JSON files (per user decision — XML and Excel deferred), DataSources with `*.xml`, `*.xlsx`, or `*.txt` patterns will never find matching files on their servers.

**Change:** When servers come from the simulator (i.e., when the `servers` list is non-empty and populated by SimulatorSeederService), bias the FilePattern assignment toward `*.csv` and `*.json` so that DataSources referencing simulator servers have patterns that match uploaded files. Specifically:

1. Keep the existing `filePatterns` array unchanged (it's used for non-simulator demo data too).

2. In the DataSource creation loop, after determining `connType` and before assigning `filePattern`, add logic:
   ```csharp
   // When servers are seeded from simulator, use CSV/JSON patterns that match uploaded files
   // (FileGeneratorService only generates .csv and .json)
   var simulatorFilePatterns = new[] { "*.csv", "*.json" };
   var effectiveFilePattern = (server != null || nasDevice != null)
       ? simulatorFilePatterns[i % simulatorFilePatterns.Length]
       : filePattern;
   ```

3. Replace `filePattern` with `effectiveFilePattern` in:
   - The `DataProcessingDataSource` initialization: `FilePattern = effectiveFilePattern`
   - The `fileConfig.type` computation: `effectiveFilePattern.TrimStart('*', '.').ToUpper()`

This ensures that DataSources linked to simulator servers expect CSV or JSON files (which are what gets uploaded), while DataSources without server links (fallback/demo) keep the original variety.
