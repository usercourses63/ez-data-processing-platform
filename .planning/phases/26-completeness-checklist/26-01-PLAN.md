    **useCompletenessTracker.ts** - Create a React hook with this signature:

    ```typescript
    export function useCompletenessTracker(
      form: FormInstance,
      jsonSchema: any,
      outputConfig: OutputConfiguration,
      initialValues?: Record<string, any>,
      isEditMode?: boolean
    ): {
      completeness: CompletenessState;
      recalculate: (changedValues: any, allValues: any) => void;
      getFieldStatus: (tabKey: string, fieldName: string) => FieldStatus;
    }
    ```

    Implementation details:
    1. Internal state: `const [completeness, setCompleteness] = useState<CompletenessState>(...)` initialized to 0% with all tabs incomplete.
    2. `computeCompleteness(allValues, jsonSchema, outputConfig, isEditMode)` function:
       - For each tab in TAB_FIELD_CONFIG:
         - If tab has `fields`: iterate fields, evaluate `when` condition against allValues. For required applicable fields, check if allValues[field.name] is truthy (not undefined, not empty string, not null). Count filled vs total.
         - If tab has `nonFormCheck`: call it with (jsonSchema, outputConfig). Result is 0/1 or 1/1.
         - For metrics tab: if !isEditMode, skip it (show as grayed out unavailable).
       - Compute requiredPercent: sum filled required fields / sum total required fields * 100.
       - Compute recommendedPercent: sum filled recommended fields / sum total recommended fields * 100 (skip metrics in create mode).
       - Build missingFields: list of field names from required tabs that are applicable but not filled.
       - Build TabCompleteness for each tab with filledCount, totalCount, isComplete.
    3. `recalculate` callback: called by Form's onValuesChange. Merges allValues with initialValues (for unvisited lazy tabs -- initialValues provides defaults for fields never mounted). Then calls computeCompleteness.
    4. `useEffect` on [jsonSchema, outputConfig]: recalculates when non-form state changes. Uses `form.getFieldsValue(true)` merged with initialValues.
    5. `useEffect` on mount: initial calculation using form.getFieldsValue(true) merged with initialValues.
    6. `getFieldStatus(tabKey, fieldName)`: returns 'filled' if value is truthy, 'required-empty' if field is required and empty, 'optional-empty' if field is not required and empty. Used by CompletenessFieldWrapper in Plan 02.

    **IMPORTANT for lazy tabs:** When a field has never been mounted, `form.getFieldsValue(true)` returns undefined for it. The hook merges initialValues (from cloneData or fetched datasource or DEFAULT_FORM_VALUES) underneath the form values: `const merged = { ...initialValues, ...form.getFieldsValue(true) }`. This ensures unvisited tabs still show correct completeness.

    **completenessUtils.ts** - Create a standalone utility for checking completeness from an API DataSource object (used by list page for enable/disable enforcement per D-16/D-17/D-21):

    ```typescript
    export function checkDataSourceCompleteness(ds: any): {
      isComplete: boolean;
      missingFields: string[];
      requiredPercent: number;
    }
    ```

    This function:
    1. Extracts fields from the DataSource API response: ds.Name, ds.SupplierName, ds.Category for basic.
    2. Parses ds.AdditionalConfiguration?.ConfigurationSettings (or ds.ConfigurationSettings) as JSON to get connectionConfig, fileConfig.
    3. Checks connection fields based on connectionConfig.type (same conditional logic as TAB_FIELD_CONFIG).
    4. Checks fileConfig.type for file tab.
    5. Checks ds.JsonSchema for schema completeness (same nonFormCheck logic).
    6. Returns { isComplete, missingFields, requiredPercent }.

    Reuse the same field definitions from TAB_FIELD_CONFIG where possible. Import REQUIRED_TABS and TAB_FIELD_CONFIG.
