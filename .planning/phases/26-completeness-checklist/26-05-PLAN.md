**GAP-02 (continued): Fix DOM attribute injection in DataSourceFormEnhanced.tsx and DataSourceEditEnhanced.tsx**

The current `useEffect` for border injection searches for fields using `[id*="${field.name}"]` and `[id$="_${field.name}"]`. This works for `<Input>` elements which have `id` set by Ant Design Form, but fails for `<Select>`, `<Switch>`, `<DatePicker>`, `<InputNumber>` which do NOT get an `id` matching the field name on their interactive element.

Replace the field-finding logic in the border injection `useEffect` in BOTH `DataSourceFormEnhanced.tsx` AND `DataSourceEditEnhanced.tsx`. The current code block looks like:

```typescript
for (const field of config.fields) {
  const formItems = container.querySelectorAll('.ant-form-item');
  for (const formItem of formItems) {
    const el = formItem.querySelector(`[id*="${field.name}"]`) ||
      formItem.querySelector(`[id$="_${field.name}"]`);
    if (el) {
      const status = getFieldStatus(tabKey, field.name);
      (formItem as HTMLElement).setAttribute('data-completeness-status', status);
      break;
    }
  }
}
```

Replace with a more robust approach that checks multiple selectors including form control wrappers:

```typescript
for (const field of config.fields) {
  const formItems = container.querySelectorAll('.ant-form-item');
  for (const formItem of formItems) {
    // Strategy 1: Match by id (works for Input, TextArea)
    const byId = formItem.querySelector(`[id*="${field.name}"]`) ||
      formItem.querySelector(`[id$="_${field.name}"]`);
    // Strategy 2: Match by data-field-name attribute we set on Form.Item
    // Strategy 3: Match by label's htmlFor attribute pointing to field name
    const label = formItem.querySelector(`label[for*="${field.name}"]`);
    // Strategy 4: For Select, look for the hidden input or the select container
    const selectInput = formItem.querySelector(`input[id*="${field.name}"]`) ||
      formItem.querySelector(`.ant-select`);

    if (byId || label || (selectInput && formItem.querySelectorAll('.ant-form-item').length === 0)) {
      const status = getFieldStatus(tabKey, field.name);
      (formItem as HTMLElement).setAttribute('data-completeness-status', status);
      break;
    }
  }
}
```

ALSO: Add a fallback -- after the field-level loop, iterate all `.ant-form-item` elements in the container that have NO `data-completeness-status` set, and check if they contain any required form control by trying to match their internal label or control to a field name. If no match, set `data-completeness-status="optional-empty"` so they at least get the gray border (better than no border).
