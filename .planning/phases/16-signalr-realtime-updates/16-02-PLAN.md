**1. Create `src/Frontend/src/hooks/useMonitoringHub.ts`:**

Adapt the file-simulator's `useSignalR.ts` hook for multi-event support. Use `@microsoft/signalr` (already in package.json v7.0.11).

```typescript
import { useEffect, useState, useRef } from 'react';
import * as signalR from '@microsoft/signalr';
import { message } from 'antd';
import { useTranslation } from 'react-i18next';
```

Export a `ConnectionState` type: `'connecting' | 'connected' | 'reconnecting' | 'disconnected'`.

Export `useMonitoringHub(hubUrl: string)` returning:
```typescript
{
  connectionState: ConnectionState;
  isConnected: boolean;
  deviceHealth: DeviceHealthStatusResponse | null;
  services: ServiceStatus[];
  pods: PodStatus[];
  metrics: DashboardMetrics | null;
  queues: MessageQueue[];
  alerts: Alert[];
  trace: DistributedTrace | null;
  clusterInfo: ClusterInfo | null;
  events: PipelineEvent[];
  lastUpdate: Date | null;
}
```

Implementation details:
- `isMountedRef = useRef(true)` -- unmount guard per file-simulator pattern
- `wasConnectedRef = useRef(false)` -- track previous connection state for toast notifications
- `HubConnectionBuilder().withUrl(hubUrl).withAutomaticReconnect([0, 2000, 5000, 10000, 30000]).configureLogging(signalR.LogLevel.Information).build()`
- Register `.on()` handlers for all 8 events + `InitialState`:
  - `'DeviceHealthUpdate'` -> setDeviceHealth
  - `'ServiceStatusUpdate'` -> setServices (map PascalCase to camelCase)
  - `'PodStatusUpdate'` -> setPods (map PascalCase to camelCase)
  - `'MetricsUpdate'` -> setMetrics (map PascalCase to camelCase, including ThroughputHistory/LatencyHistory/ErrorHistory arrays of {Timestamp, Value} -> {timestamp: new Date(ts), value})
  - `'QueueStatusUpdate'` -> setQueues (map PascalCase to camelCase)
  - `'AlertUpdate'` -> setAlerts (map PascalCase to camelCase)
  - `'TraceUpdate'` -> setTrace (map PascalCase to camelCase)
  - `'PipelineEventUpdate'` -> setEvents using rolling buffer: `setEvents(prev => [mapPipelineEvent(raw), ...prev].slice(0, 50))` — map PascalCase {Id, Timestamp, Service, Level, Message, CorrelationId} to camelCase PipelineEvent
  - `'InitialState'` -> sets ALL fields from the snapshot (DeviceHealth, Services, Pods, Metrics, Queues, Alerts, Trace, ClusterInfo, PipelineEvents)
- Every `.on()` handler checks `if (!isMountedRef.current) return;` before calling setState
- Every handler calls `setLastUpdate(new Date())` after setting data
- `connection.onreconnecting()` -> set connectionState to 'reconnecting', show `message.warning(t('monitoring.connection.lost'), 5)` ONLY if wasConnectedRef was true
- `connection.onreconnected()` -> set connectionState to 'connected', show `message.success(t('monitoring.connection.restored'), 3)`
- `connection.onclose()` -> set connectionState to 'disconnected'
- `connection.start()` -> on success set connectionState to 'connected', wasConnectedRef = true
- Cleanup: set isMountedRef to false, call connection.stop()
- `isConnected` computed as `connectionState === 'connected'`

All data state types must use the EXISTING types from `monitoring.types.ts`, `kubernetes.types.ts`, and `device-health.types.ts`. The backend sends PascalCase but the existing frontend types use camelCase for some fields (ServiceStatus, PodStatus, etc.) and PascalCase for device-health. Add a mapper function for each camelCase type:

```typescript
function mapServiceStatus(raw: any): ServiceStatus {
  return {
    id: raw.Id, name: raw.Name, displayName: raw.DisplayName, status: raw.Status,
    port: raw.Port, icon: raw.Icon ?? '', cpu: raw.Cpu, memory: raw.Memory,
    throughput: raw.Throughput, errorRate: raw.ErrorRate, latency: raw.Latency,
    uptime: raw.Uptime, restarts: raw.Restarts, queueDepth: raw.QueueDepth,
  };
}
```

Similar mappers for PodStatus (raw.Name->name, raw.Service->service, raw.Status->status mapping "Running"->"running" etc.), DashboardMetrics (raw.TotalThroughput->totalThroughput, raw.ThroughputHistory->throughputHistory mapping each {Timestamp, Value} to {timestamp: new Date(ts), value}, same for LatencyHistory and ErrorHistory), MessageQueue (raw.Name->name, raw.Topic->topic, etc.), Alert (raw.Id->id, raw.Type->type, etc.), DistributedTrace (raw.TraceId->traceId, etc.), ClusterInfo (raw.ClusterName->clusterName, etc.), PipelineEvent (raw.Id->id, raw.Timestamp->new Date(timestamp), raw.Service->service, raw.Level->level, raw.Message->message, raw.CorrelationId->correlationId). DeviceHealthStatusResponse already uses PascalCase so no mapping needed.
