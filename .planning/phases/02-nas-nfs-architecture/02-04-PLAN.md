**Key insight from research:** NFS mounts appear as local filesystem paths via PVC. The connector uses standard File/Directory APIs, but with NAS-specific mount path resolution.

```csharp
/// <summary>
/// Connector for reading files from NFS via Kubernetes PersistentVolume mounts.
/// NFS shares are mounted to pod filesystem via PVC; this connector accesses those mounts.
///
/// Mount path convention: /mnt/{nas-device-name}
/// Example: NAS device "input-1" mounts to /mnt/input-1
///
/// v0.2.0: Part of NAS/NFS Architecture (Phase 2)
/// </summary>
public class NfsConnector : IDataSourceConnector, IServerConnector
{
    private readonly ILogger<NfsConnector> _logger;

    public string ConnectorType => "nfs";

    public NfsConnector(ILogger<NfsConnector> logger)
    {
        _logger = logger;
    }
```

**IDataSourceConnector Implementation:**

ReadFileAsync:
- Construct full path from dataSource.FilePath (mount path) + filePath
- Verify file exists
- Read into MemoryStream (same as LocalFileConnector)
- Log with NFS context

ListFilesAsync:
- Use DirectoryInfo.EnumerateFiles (better for network/FUSE filesystems)
- Handle Directory not existing gracefully (NFS mount might not be ready)
- Log number of files found

TestConnectionAsync:
- Check if mount directory exists
- Try to enumerate files (tests read permission)
- Return true if successful

GetFileMetadataAsync:
- Return FileMetadata with size, dates, content type

**IServerConnector Implementation:**

For AdminServer-based access:

TestConnectionAsync(AdminServer server, ...):
- Check if server.BasePath directory exists
- Return ConnectionTestResult with timing

ListFilesAsync(AdminServer server, ...):
- Enumerate files from server.BasePath + path
- Return DiscoveredFile list

ReadFileAsync(AdminServer server, ...):
- Read file from server.BasePath + filePath
- Return byte[]

WriteFileAsync(AdminServer server, ...):
- Write to server.BasePath + filePath
- Create directory if needed

**Important differences from LocalFileConnector:**

1. ConnectorType is "nfs" not "local"
2. Log messages include "NFS" context for debugging mount issues
3. Handle mount not ready scenario (directory doesn't exist yet)
4. Include comments explaining the PVC mount pattern
