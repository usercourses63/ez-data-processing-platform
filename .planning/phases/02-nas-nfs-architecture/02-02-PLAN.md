**Step 2: Create KubernetesConfiguration.cs**
Location: src/Services/Shared/Configuration/KubernetesConfiguration.cs
Namespace: DataProcessing.Shared.Configuration

Create extension method AddKubernetesClient that:

1. Registers Kubernetes client as Singleton
2. Auto-detects environment:
   - Try InClusterConfig() first (for K8s/OCP pods)
   - Fall back to kubeconfig for local development
3. Reads configuration from IConfiguration:
   - Kubernetes:Context (default: "minikube")
   - Kubernetes:KubeConfigPath (optional override)
   - Kubernetes:Namespace (default: "ez-platform")

Handle KubeConfigException gracefully when InClusterConfig fails.

Use the pattern from 02-RESEARCH.md:
```csharp
public static class KubernetesConfiguration
{
    public static IServiceCollection AddKubernetesClient(
        this IServiceCollection services,
        IConfiguration configuration)
    {
        services.AddSingleton<k8s.Kubernetes>(sp =>
        {
            var logger = sp.GetRequiredService<ILogger<k8s.Kubernetes>>();

            try
            {
                // Try in-cluster config first
                var config = KubernetesClientConfiguration.InClusterConfig();
                logger.LogInformation("Using in-cluster Kubernetes configuration");
                return new k8s.Kubernetes(config);
            }
            catch (k8s.Exceptions.KubeConfigException)
            {
                // Fall back to kubeconfig
                var contextName = configuration["Kubernetes:Context"] ?? "minikube";
                var kubeConfigPath = configuration["Kubernetes:KubeConfigPath"];

                var config = KubernetesClientConfiguration.BuildConfigFromConfigFile(
                    kubeConfigPath,
                    contextName);

                logger.LogInformation("Using kubeconfig with context {Context}", contextName);
                return new k8s.Kubernetes(config);
            }
        });

        return services;
    }
}
```

IMPORTANT: Use fully qualified type `k8s.Kubernetes` to avoid conflicts with namespace.

    Task<V1PersistentVolumeClaim?> GetPersistentVolumeClaimAsync(string pvcName, string namespace_, CancellationToken ct = default);
    Task<bool> DeletePersistentVolumeClaimAsync(string pvcName, string namespace_, CancellationToken ct = default);

    // Deployment operations

**CreatePersistentVolumeAsync implementation:**
Build V1PersistentVolume from NasDevice:
- Name: device.PvName
- Labels: type=nfs, nas-role={device.Role}, nas-device={device.Name}, managed-by=ez-platform
- Capacity: device.StorageCapacity
- AccessModes: [device.AccessMode]
- ReclaimPolicy: device.ReclaimPolicy
- NFS source: Server=device.Host, Path=device.ExportPath, ReadOnly based on role
- MountOptions: device.MountOptions

Handle HttpOperationException with StatusCode 409 (Conflict) by reading existing PV.

**CreatePersistentVolumeClaimAsync implementation:**
Build V1PersistentVolumeClaim:
- Name: device.PvcName
- Namespace: namespace_
- AccessModes: [device.AccessMode]
- Resources.Requests["storage"]: device.StorageCapacity
- Selector.MatchLabels: { "nas-device": device.Name.ToLower() }
- StorageClassName: null (static binding - do NOT set to empty string)

**GetPvcBindingStatusAsync:**
Return pvc.Status.Phase (Pending, Bound, Lost, etc.)

**WaitForPvcBoundAsync:**
Poll every 2 seconds until PVC phase is "Bound" or timeout.

**AddNasMountToDeploymentAsync:**
1. Read deployment
2. Add volume to spec.template.spec.volumes:
   - Name: "nas-{device.Name.ToLower()}"
   - PersistentVolumeClaim.ClaimName: device.PvcName
3. Add volumeMount to first container:
   - Name: "nas-{device.Name.ToLower()}"
   - MountPath: device.MountPath
   - ReadOnly: device.Role == NasDeviceRole.Backup
4. Replace deployment

Log all operations with structured logging including device name, PV/PVC names.
