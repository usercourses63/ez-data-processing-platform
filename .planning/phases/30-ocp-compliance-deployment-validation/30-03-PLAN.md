  <files>scripts/clean-deploy.sh</files>
  <action>
    Create `scripts/clean-deploy.sh` — a bash script that performs the full D-02 pipeline:

    ```
    #!/usr/bin/env bash
    # Clean Deploy Pipeline for EZ Platform
    # Full wipe + Helm install + seed + port-forward
    # Usage: bash scripts/clean-deploy.sh [--skip-seed] [--skip-portforward]
    ```

    **Script phases:**

    **Phase 1: Pre-flight checks**
    - Verify kubectl, helm, dotnet are available
    - Verify minikube is running: `minikube status`
    - Accept `--skip-seed` and `--skip-portforward` flags
    - Print warning: "This will DELETE all data in ez-platform namespace. Continue? [y/N]"
    - Skip prompt if `--yes` flag provided

    **Phase 2: Namespace wipe**
    - `kubectl delete namespace ez-platform --ignore-not-found --wait=true --timeout=120s`
    - Wait for namespace to be fully gone: poll `kubectl get namespace ez-platform` until 404
    - `kubectl create namespace ez-platform`

    **Phase 3: Helm install**
    - `helm install ez-platform ./helm/ez-platform -n ez-platform -f helm/ez-platform/values.yaml -f helm/ez-platform/values-dev.yaml`
    - If Helm install fails, print error and exit 1

    **Phase 4: Wait for pods**
    - Wait for infrastructure first (MongoDB, Kafka, Hazelcast):
      `kubectl wait --for=condition=ready pod -l app=mongodb -n ez-platform --timeout=300s`
      `kubectl wait --for=condition=ready pod -l app=kafka -n ez-platform --timeout=300s`
    - Then wait for all pods:
      `kubectl wait --for=condition=ready pod --all -n ez-platform --timeout=600s`
    - Print pod status: `kubectl get pods -n ez-platform`
    - If any pod not ready after timeout, print logs of failing pods and exit 1

    **Phase 5: MongoDB replica set init (if needed)**
    - Check if MongoDB needs rs.initiate():
      ```bash
      kubectl exec -n ez-platform mongodb-0 -- mongosh --eval "rs.status()" 2>/dev/null | grep -q "ok"
      if [ $? -ne 0 ]; then
        kubectl exec -n ez-platform mongodb-0 -- mongosh --eval 'rs.initiate({_id:"rs0",members:[{_id:0,host:"mongodb-0.mongodb:27017"}]})'
      fi
      ```

    **Phase 6: Port forwarding**
    - Unless `--skip-portforward`, start port forwards:
      `powershell.exe -ExecutionPolicy Bypass -File scripts/start-port-forwards.ps1 &`
    - Wait 5 seconds for port forwards to establish
    - Verify key ports responding:
      `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5001/health`

    **Phase 7: Seed data**
    - Unless `--skip-seed`:
      ```bash
      cd tools/DemoDataGenerator
      dotnet run -- --direct-connection
      ```
    - Verify seeding: `curl -s http://127.0.0.1:5001/api/v1/datasource | head -c 200`

    **Phase 8: Summary**
    - Print deployed pod count, namespace status
    - Print access URLs (frontend: http://localhost:7000, etc.)
    - Print next steps: "Run sanity tests: cd src/Frontend && npm run test:e2e:sanity"

    **Error handling:**
    - `set -euo pipefail` at top
    - Each phase prints "[Phase N/8] Description..." before executing
    - On failure, print which phase failed and suggest remediation
    - Trap EXIT to print status on any failure

    **Important:**
    - The script should work on Windows Git Bash (where the project runs)
    - Use `powershell.exe` for port forwarding (Windows-specific, per CLAUDE.md)
    - DemoDataGenerator uses `--direct-connection` for localhost MongoDB access
    - MongoDB might already have replica set initialized — handle idempotently
  </action>
